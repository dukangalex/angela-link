# 通用化路线图（ROADMAP）

AngelaLink 的定位是**通用本地 AI 桥**：电脑端守授权、沙箱、审批与审计，
AI 端只面对一组稳定接口。上游 MuseLink 的接口层（/agent/v1）本来就是
普通 HTTP＋Bearer 令牌，与任何单一 AI 产品无关；绑定只在品牌、文案与
接入引导里。通用化就是把这三处解绑，分三步走。

## 第一步：自有化与文档中立（已落地，导入版）
- 自有命名 AngelaLink、自有 README/AGENTS/CREDITS，致谢与许可证保留。
- 剥离上游社区引流（LINUX DO），下载链接换自有仓。
- 接入说明改为中立版（docs/AGENT-BRIEF.md）：任何 AI 按同一份说明接入；
  Muse 的连接器卡片流程只是其中一种保管令牌的方式，不再是唯一路径。

## 第二步：代码标识中立化（v0.3.0 已落地核心三项）
- crate 与目录名 muse-connector → angela-link；数据目录 ~/.muse-bridge
  → ~/.angela-link（带旧目录一次性迁移，老令牌不失效）。✔
- 令牌前缀 mfa_ → ala_（新旧双认一个版本周期，日志脱敏同步覆盖两种形状）。✔
- 顺带完成：凭证保护清单扩围（.azure/.kube/.docker、浏览器密码库、gcloud）。
- 待续：界面与日志中的「Muse 专用」字样改为「AI 接入」中立表述；
  「接入说明」生成器输出中立版说明＋可选的 Muse 连接器版说明（部署配置选）。

## 第三步：MCP 传输（方向已定，排期看需求）
- 在 /agent/v1 之外加一层 MCP server 适配（stdio 不适用，走 streamable HTTP），
  让支持 MCP 的 agent 零改动接入；REST 接口保留为基础契约，两者共用同一套
  授权、沙箱与审批，不许出现第二条绕开审批的路径。
- 多接入方管理：令牌按接入方命名与独立撤销（现为单 agent 令牌＋旧版令牌，
  扩为命名令牌表，审计日志记录接入方名）。

## 不做
- 不做云端中继、不托管令牌、不收集遥测：桥永远在用户自己的电脑上，
  隧道用用户自己的 Tailscale/Cloudflare 账号。
- 不为「通用」牺牲安全边界：任何新传输层都必须复用同一套审批与沙箱。
